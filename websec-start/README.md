# WebSec Start

Учебная платформа по веб-пентесту для начинающих. Интерфейс на русском, узбекском и английском.

- **Теория по OWASP Top 10:2025** — 10 тем: объяснение, разбор кода «уязвимо / исправлено», как искать и как исправлять.
- **CTF-лаборатории** — по одной на тему (31 шаг всего). Сценарий, цели, подсказки без готовых команд и терминал, в котором нужно самому найти флаг.
- **Бонус-цепочки** — две лаборатории, где несколько слабостей идут подряд (бэкап → вход → IDOR; хранимый XSS → кража сессии).
- **Терминал-симулятор** — `curl` (а также `wget` и httpie), `nmap`, `whatweb`, `ffuf`, `nikto`, `sqlmap`, `testssl.sh`, `trivy`, `cat`, `nano`, `echo`, `ls`, `login`. Реальная сеть не используется, все ответы выдуманные.
- **Каталог инструментов** — установка, пошаговая инструкция и примеры команд. Burp Suite и ZAP — графические, для них подробная инструкция вместо терминала.
- **Аккаунты, прогресс и рейтинг** — вход с любого устройства (после деплоя на Netlify).

## Как устроено хранение пользователей

Сайт сам определяет, есть ли рядом сервер:

| Режим | Когда | Где лежат аккаунты и прогресс | Рейтинг |
|---|---|---|---|
| **Серверный** | сайт задеплоен на Netlify из Git (работает `/api`) | на сервере, в Netlify Blobs; вход с любого устройства | есть |
| **Локальный** | `index.html` открыт как файл, на GitHub Pages или в любом статическом хостинге без `/api` | в `localStorage` этого браузера, между устройствами не переносится | нет |

Серверная часть — один файл `netlify/functions/api.mjs`. Внешние сервисы и отдельные аккаунты не нужны, используется встроенное хранилище Netlify Blobs.

- Пароли хранятся только как хеш (PBKDF2-SHA256, 120 000 итераций, своя соль у каждого пользователя). Сессия — случайный токен на 30 дней.
- После 8 неверных паролей подряд вход блокируется на 10 минут.
- Прогресс сохраняется сам, через долю секунды после каждого шага. В шапке индикатор: зелёная точка — сохранено, жёлтая — сохраняется, красная — нет связи (повторит при следующем действии или когда появится сеть).
- Пользователь может удалить аккаунт на странице «Прогресс».

Что нужно знать:
- **Рейтинг держится на доверии.** Лаборатории работают в браузере, флаги лежат в коде страницы, поэтому результат технически можно подделать. Сервер проверяет только форму данных (известные лаборатории, корректное число шагов).
- Регистрация открытая, без капчи и без почты. Восстановления пароля нет, а имена игроков в рейтинге публичны.
- Мини-миссии и прогресс хранятся только у того, кто вошёл в аккаунт.

## Структура репозитория

```
.
├── index.html                    ← вся платформа (HTML + CSS + JS)
├── netlify/functions/api.mjs     ← сервер: аккаунты, прогресс, рейтинг
├── package.json                  ← зависимость @netlify/blobs
├── netlify.toml                  ← настройки Netlify
├── .gitignore
└── README.md
```

## Публикация: GitHub → Netlify

Серверный режим работает только при деплое из Git. Если просто перетащить папку в Netlify (drag and drop), функции не развернутся и сайт будет работать в локальном режиме.

1. Создайте пустой репозиторий на GitHub (без README и .gitignore) и выполните в папке проекта:
   ```bash
   git init
   git add .
   git commit -m "WebSec Start"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
   git push -u origin main
   ```
2. На [app.netlify.com](https://app.netlify.com): **Add new site → Import an existing project → GitHub**, выберите репозиторий.
3. Build command оставьте пустым, Publish directory — `.` (всё уже указано в `netlify.toml`). Нажмите **Deploy**.
4. Каждый следующий `git push` в `main` будет выкатываться автоматически.

### Проверка после первого деплоя

Серверную часть я проверял локально на тестовом хранилище, на самом Netlify она ещё не запускалась. Поэтому после деплоя проверьте:

1. Откройте `https://<ваш-сайт>.netlify.app/api/ping`. Должно вернуться `{"ok":true}`.
2. Зарегистрируйтесь, захватите любой шаг лаборатории и подождите секунду: точка в шапке станет зелёной.
3. Откройте сайт в другом браузере или в режиме инкогнито и войдите под тем же аккаунтом. Прогресс должен быть на месте. В навигации должна появиться вкладка «Рейтинг».
4. Если `/api/ping` отвечает 404, смотрите вкладку **Logs → Functions** на Netlify: функция должна называться `api`.

### Локальный запуск

```bash
npm install
npx netlify dev     # сайт + функции на http://localhost:8888
```
Без Netlify CLI можно просто открыть `index.html`: сайт заработает в локальном режиме.

Свой домен: Site configuration → Domain management → Add custom domain.

## Где что менять в `index.html`

| Что менять | Что искать |
|---|---|
| Тексты интерфейса и теория (ru / uz / en) | `TEXT.ru =`, `TEXT.uz =`, `TEXT.en =` |
| Шаги, команды и вывод лабораторий | `const LAB_DEFS` |
| Описания шагов, подсказки, итоговый текст | `const LAB_TEXT` |
| Бонус-цепочки | `const BONUS` и записи `b01`, `b02` |
| Инструменты и примеры команд | `const TOOLS` |
| Цвета и шрифты | блок `:root{ ... }` в начале `<style>` |
| Ответы терминала на общие команды | `function cmdOutput` |

Чтобы добавить шаг в лабораторию, добавьте объект в `steps` в `LAB_DEFS` и по одной строке в `steps` и `hints` для каждого языка в `LAB_TEXT`. Флаг должен быть в выводе последнего шага: лаборатория засчитывается, когда выполнен последний шаг. Новое число шагов нужно указать и в таблице `STEPS` в `netlify/functions/api.mjs`, иначе сервер не сохранит прогресс по такой лаборатории.

## Правила использования

Всё, что здесь изучается, применяйте только к системам, на тестирование которых у вас есть письменное разрешение: свои стенды, CTF-площадки, bug bounty. Сканирование чужих сайтов без разрешения — уголовно наказуемо.
